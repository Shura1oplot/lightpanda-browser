## Сохраненные доработки

1. Профиль Chrome 146 применяется после каждого сброса соединения libcurl. Ошибка применения профиля останавливает подготовку соединения. Переменные `CURL_IMPERSONATE` и `CURL_IMPERSONATE_HEADERS` не меняют выбранный профиль.

2. Заголовки HTTP, Navigator и ответ CDP `Browser.getVersion` сохраняют Chrome 146. User-Agent зависит от целевой операционной системы, как в прежней сборке.

3. `Russian Trusted Root CA` добавляется к стандартному системному хранилищу. Явные `--ca-cert` и `--ca-path` заменяют стандартное хранилище. Тесты проверяют отпечаток DER `d26d2d0231b7c39f92cc738512ba54103519e4405d68b5bd703e9788ca8ecf31` и повторное добавление корня.

4. Файл cookies сохраняется атомарно с правами `0600` и синхронизацией перед заменой. Закрытие контекста CDP сохраняет cookies в режиме сервера. Загрузка через `--cookie` и сохранение через `--cookie-jar` работают вместе.

5. Регрессионный тест WebSocket сохраняет коды закрытия `1002` при ошибке протокола и `1001` при обычном завершении.

6. Внешний полный статический архив, заголовки curl, настройки SDK, точная полная версия и отдельные каталоги сборки для платформ сохранены. Исполняемые файлы не зависят от динамических `libcurl`, `libssl` и `libcrypto`.

## Исправления совместимости

1. Профиль curl содержит значения заголовков для навигации. Новый тест Lightpanda обнаружил лишний `Sec-Fetch-User: ?1` в обычном запросе JavaScript. Транспорт теперь подавляет отсутствующие заголовки `Sec-Fetch-*`, сохраняя значения, которые сформировал Lightpanda. Существующий тест проверяет результат через настоящий локальный HTTP-сервер.

2. Новый тест Unix-сокета создавал абсолютный путь длиной 110 байт. Это превышает предел 104 байта на macOS. Тест использует короткий относительный путь внутри своего временного каталога. Проверки абсолютного пути в команде `--unix-socket` не изменены.

3. Сценарий использует `-Doptimize=fast` и переменную `ZIG_GLOBAL_CACHE_DIR`, как требует Zig `0.17.0`.

## Проверки готовых файлов

1. На всех трех платформах `example.com` и `rzd.ru` вернули HTTP `200`. Сайт `self-signed.badssl.com` отклонен с `PeerFailedVerification` и кодом выхода `1`. На macOS arm64 и Linux arm64 также отклонен `untrusted-root.badssl.com`.

2. На macOS arm64 и Linux arm64 нейтральная проверка CDP использовала те же параметры запуска сервера и cookies, что соединитель ConsultantPlus. Проверены Chrome 146, разрешенный запрос того же источника, отклоненный запрос другого источника без CORS и HTTP `403` для постороннего Origin.

3. На macOS arm64 и Linux arm64 в новом временном каталоге проверены сохранение cookies, права `0600`, перезапуск и повторная загрузка. Существующие сеансы и учетные записи не использовались.

4. На всех трех платформах через `tls.peet.ws/api/all` Lightpanda совпал с эталоном `curl_chrome146` по JA4 и отпечатку HTTP/2.

4.1 JA4: `t13d1516h2_8daaf6152771_d8a2da3f94cd`.

4.2 HTTP/2: `1:65536;2:0;4:6291456;6:262144|15663105|0|m,a,s,p`.

5. Стандартный профиль `curl_chrome146` использует User-Agent Macintosh даже на Linux. На Linux эталон получает явный User-Agent Linux из прежней настройки Lightpanda. JA4 и HTTP/2 совпали до этого уточнения; первичное различие User-Agent сохранено в свидетельствах. Итоговый User-Agent соответствует сохраненной настройке целевой платформы.

6. Файл macOS имеет формат Mach-O arm64, содержит `_curl_easy_impersonate` и прошел проверку подписи `ad-hoc` командой `codesign`. `tools/bin/macos-arm64/lightpanda` совпадает побайтово с установленной командой `~/.local/bin/lightpanda`.

7. На Linux amd64 дополнительно прошли 17 проверок curl TLS, WebSocket и WebCrypto и две проверки HTTP/2. Отдельная проверка CDP, cookies и постороннего Origin на рабочем сервере относится к приемке развертывания; ее результат пока не заявлен.

## Ограничения

1. Новая готовая библиотека V8 требует macOS `13.0`. Сценарий и итоговый Mach-O задают тот же минимум. Запуск на macOS `13.0` отдельно не проверялся; проверена macOS `26.6.2`.

2. Linux arm64 проверен в нативном контейнере Ubuntu `24.04.5`. Отдельная физическая машина ARM64 не использовалась. Linux amd64 собран на временном VPS Ubuntu `24.04` с четырьмя процессорами, 8 ГБ памяти и 8 ГБ подкачки. После экспорта файлов временный сервер удален. Системы с musl, Intel macOS и Windows не входят в приемку.

3. Приемка не включает авторизованные операции ConsultantPlus и других соединителей. Проверка CDP подтверждает их параметры запуска и механизм cookies на нейтральной странице.

## Повторение сборки

```bash
scripts/build-lightpanda.sh
```

Сценарий собирает статический curl, снимок V8 и исполняемый файл. Затем он выполняет полный набор тестов с неверными переменными профиля curl. Готовый файл попадает в каталог своей платформы после успешных тестов. Команда `runtimes/lightpanda/install.sh` устанавливает готовый файл текущей платформы атомарно.
