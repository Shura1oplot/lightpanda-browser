macOS arm64 обновлена на официальный стабильный выпуск Lightpanda `0.4.1` с сохранением изменений владельца репозитория. Файлы Linux сохраняют выпуск от 1 сентября 2026 года. Проверки новой сборки относятся только к macOS arm64.

Версия `0.4.1-curl-impersonate8.22.0-20260927174013` содержит стабильную основу Lightpanda, версию встроенного curl и время начала сборки 27 сентября 2026 года в 17:40:13 UTC. Сведения Git к этому значению не добавляются.

- Фиксация с изменениями владельца составляет `1bf7541d7f571ce33b73e1fae11d346d8799b962`. Исходное дерево при сборке было чистым.

## Сохраненные изменения

- Профиль Chrome 146 применяется после каждого повторного сброса соединения libcurl. Заголовки HTTP и данные Navigator сохраняют ту же версию Chrome.
- Официальный `Russian Trusted Root CA` добавляется к стандартному хранилищу внутри Lightpanda. Явные `--ca-cert` и `--ca-path` заменяют стандартное хранилище без добавления этого корня.
- Полученная ошибка WebSocket обрабатывается до общего завершения соединения. Проверка сохраняет коды закрытия `1002` для ошибки протокола и `1001` для обычного завершения. В выпуске `0.4.1` этот порядок уже обеспечен официальным кодом; локальный регрессионный тест перенесен на его новый интерфейс.
- Сохранение файла cookies в режиме сервера остается доступным.

## Проверки macOS

- `zig fmt --check` и `zig build ... check` завершились успешно.
- Полный запуск тестов завершился результатом `1532 of 1532 tests passed` с заведомо неверными значениями `CURL_IMPERSONATE` и `CURL_IMPERSONATE_HEADERS`.
- Снимок V8 и исполняемый файл собраны в режиме `ReleaseFast`.
- Файл имеет формат Mach-O arm64, содержит `_curl_easy_impersonate` и не зависит от внешних `libcurl`, `libssl` или `libcrypto`. Проверка специальной подписи macOS завершилась успешно.
- `example.com` и `rzd.ru` вернули HTTP `200`. Недоверенный сертификат `self-signed.badssl.com` отклонен с `PeerFailedVerification` и кодом завершения `1`.
- Испытание перед изменением формата версии через `tls.peet.ws/api/all` без `CURL_IMPERSONATE` показало совпадение Lightpanda с эталонным запросом curl-impersonate Chrome 146. Значение JA4 составило `t13d1516h2_8daaf6152771_d8a2da3f94cd`, отпечаток HTTP/2 составил `1:65536;2:0;4:6291456;6:262144|15663105|0|m,a,s,p`. Значения User-Agent также совпали.

Журналы сборки с итоговой версией и повторных сетевых проверок находятся в `.lp-cache/acceptance-version-2026-09-27` от корня Lightpanda. Предыдущие проверки, включая сравнение сетевого профиля, сохранены в `.lp-cache/acceptance-2026-09-27`. Итоговый файл установлен через `install.sh`; точный вывод команды `version` и побайтовое совпадение установленного файла с `tools/bin/macos-arm64/lightpanda` проверены.

Отдельная проверка сценария подтвердила одинаковую версию трех этапов сборки, новое время при повторном запуске и работу без служебных данных Git. Пустая или неверная версия curl останавливает сборку. Параметр `-Dversion=nightly` сохраняет прежнее добавление номера и идентификатора фиксации Git. Предупреждения JavaScript страницы `rzd.ru` сохранены отдельно; они не помешали получению HTTP `200` и не связаны с проверкой сертификатов.

## Повторение сборки macOS

Текущий сценарий запускается из корня Zemlekop:

```bash
scripts/build-lightpanda.sh
```

Сценарий собирает текущую платформу, включая статический curl-impersonate, снимок V8 и тесты. Он берет базовую версию из `build.zig.zon`, версию встроенного curl из `install/include/curl/curlver.h` своей статической сборки и один раз получает текущее время UTC. Все этапы получают один полный параметр `-Dversion` в формате `0.4.1-curl-impersonate8.22.0-YYYYMMDDHHMMSS`. Для Ubuntu amd64 из macOS используется `scripts/build-lightpanda-linux-amd64.sh`. Порядок и зависимости описаны в [`../../../scripts/README.md`](../../../scripts/README.md). Эти сценарии заменяют команды прежних отчетов о сборке.

После изменения формата версии полный сценарий сборки и все тесты выполнены успешно из чистой фиксации. Две независимые сборки на побайтовую воспроизводимость не сравнивались. Linux при этом обновлении не собирался и не проверялся; его прежние свидетельства находятся в `previous-2026-09-01/RELEASE.md`. Платные серверы не создавались.
