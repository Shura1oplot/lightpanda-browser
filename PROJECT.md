# Интеграция Lightpanda с curl-impersonate

## Цель

Lightpanda должен применять сетевой профиль Chrome 146 ко всем соединениям libcurl без переменной окружения и сохранять профиль после повторного использования соединения.

Интеграция изменяет TLS- и HTTP-параметры libcurl. Она не превращает DOM, JavaScript и CDP Lightpanda в полную копию Chrome.

## Текущее решение

- [`build/RELEASE.md`](build/RELEASE.md) служит единственным источником версии, исходных фиксаций, состава, контрольных сумм и результатов проверки текущего выпуска.
- Локальная ветка `main` объединяет официальный стабильный выпуск Lightpanda `0.4.0` и принятые локальные изменения сетевого профиля, сертификатов и WebSocket.
- Lightpanda связывается с внешним полным статическим архивом curl-impersonate и совместимыми заголовками.
- macOS arm64 обновляется на Lightpanda `0.4.0` и curl-impersonate `8.22.0`. Файлы Linux arm64 и Linux x86-64 сохраняют предыдущую сборку. Версии каждой платформы и результаты проверки записаны в документе выпуска.
- Apple SecTrust отключен. Lightpanda передает в BoringSSL собственное хранилище сертификатов.
- Lightpanda сохраняет системное хранилище и добавляет к нему официальный `Russian Trusted Root CA` Минцифры России. Отдельно устанавливать сертификат в операционную систему не нужно.
- Среды и способы сборки различаются по платформам; их точные параметры находятся только в документе выпуска.

## Критерии завершения

- `curl_easy_impersonate` вызывается после каждого `curl_easy_reset` для профиля, соответствующего версии Chrome в `Config.HttpHeaders`.
- Профиль применяется с заголовками браузера и не требует `CURL_IMPERSONATE`.
- Ошибка применения профиля прекращает подготовку соединения и не заменяется обычными параметрами libcurl.
- Модульные тесты проверяют выбранный профиль и успешное применение через связанный архив curl-impersonate.
- Сборки macOS arm64, Linux arm64 и Linux x86-64, форматирование и тесты Lightpanda проходят.
- Запрос Lightpanda без `CURL_IMPERSONATE` получает профиль, совпадающий с эталонным запросом curl-impersonate для Chrome 146 по проверяемым TLS- и HTTP/2-полям.
- Проверка сертификата остается включенной; посторонний центр сертификации отклоняется.
- Модульные тесты проверяют точный отпечаток встроенного `Russian Trusted Root CA` и повторное добавление сертификата в хранилище.
- `rzd.ru` возвращает HTTP-ответ без ошибки проверки цепочки сертификатов.

## Ограничения

- Статический архив зависит от операционной системы и архитектуры.
- Проверка трех целевых платформ не означает готовность Intel macOS или Windows.
- Требования к glibc различаются для Linux arm64 и Linux x86-64 и зафиксированы в документе выпуска; системы с musl не поддерживаются.
- Профиль Chrome действует на весь сетевой клиент Lightpanda. Выбор профиля для отдельного запроса не входит в текущую задачу.
- Проверка сетевого отпечатка зависит от доступности внешней испытательной службы и фиксируется отдельно от обязательных локальных тестов.
- Встроенный корень расширяет доверие на все действительные цепочки, выпущенные `Russian Trusted Root CA`, а не только на `rzd.ru`. Происхождение, контрольные суммы исходного и сохраненного файлов и отпечаток DER записаны в `src/network/certificates/README.md`.
- Явные параметры `--ca-cert` и `--ca-path` по-прежнему полностью заменяют стандартное хранилище. Встроенный корень добавляется только к стандартному системному хранилищу.

## Выпуск

Текущий выпуск содержит файлы для macOS arm64, Linux arm64 и Linux x86-64. Состав и свидетельства находятся в [`build/RELEASE.md`](build/RELEASE.md). Установщик автоматически выбирает только macOS arm64 и Linux x86-64; автоматическая установка Linux arm64 пока не реализована.

Установка готового бинарного файла из локального выпуска:

```bash
./install.sh
~/.local/bin/lightpanda version
```

Установщик проверяет SHA-256 по `build/SHA256SUMS` и не обращается к сети.

Сертификат центра уже включен в исполняемые файлы macOS и Linux. Проверяемый способ подтвердить подключение после установки:

```bash
~/.local/bin/lightpanda fetch --json --wait-until done \
  --terminate-ms 30000 https://rzd.ru/
```

Поле `http_status` должно быть больше нуля, а журнал не должен содержать `PeerFailedVerification`. Код HTTP может зависеть от политики сайта. Устанавливать сертификат в системное хранилище отдельно не нужно.

Критерии готовности выпуска:

- Исходники Lightpanda и curl-impersonate зафиксированы в чистых рабочих деревьях, а их полные идентификаторы записаны в выпуске.
- Снимок V8 и Lightpanda собраны в режиме `ReleaseFast` с явными путями к полному статическому архиву curl-impersonate и его заголовочным файлам.
- Каждый исполняемый файл Linux собран и проверен в среде своей архитектуры, записанной в документе выпуска.
- Форматирование, проверка сборки и все модульные тесты завершены успешно с заведомо неверными значениями `CURL_IMPERSONATE` и `CURL_IMPERSONATE_HEADERS`.
- Итоговые файлы соответствуют заявленным операционным системам и процессорам, содержат `curl_easy_impersonate` и не имеют динамических зависимостей от `libcurl`, `libssl` и `libcrypto`.
- Каталог выпуска содержит `lightpanda-aarch64-macos`, `lightpanda-aarch64-linux`, `lightpanda-x86_64-linux`, `SHA256SUMS`, `RELEASE.md`, `LICENSE` и `LICENSING.md`; записанные контрольные суммы проверены повторно.
- Доступ к `example.com`, получение HTTP-ответа от `rzd.ru` и отклонение недоверенного сертификата проверены отдельно каждым итоговым исполняемым файлом.

Сборка macOS x86_64, Windows, подпись macOS удостоверением разработчика, нотариальное заверение и публикация в удаленном хранилище исходников не входят в этот выпуск.
